# SkyLanes: conflict-aware drone corridor routing with QAOA

**Domain:** 1. UAVs & Robotics
**One-line problem:** A drone-fleet dispatcher (e.g. a utility running post-storm power-line inspections) must give each of N drones one flight corridor out of a few candidates, trading total flight energy against shared airspace segments (collision risk / forced holding), with every drone flying exactly one corridor.

**Origin story for the pitch:** this is the same "many nets competing for limited tracks" problem chip designers solve when routing wires, moved from silicon into low-altitude airspace.

---

## 1. Identify: problem and users

- **Users:** inspection/delivery drone operators and UTM (UAV traffic management) planners who batch-plan missions before launch.
- **Why it is hard:** choosing one route per drone is easy *alone* (shortest path is polynomial). The difficulty is the **coupling**: drone A's best corridor may overlap drone B's, so the choices must be made jointly. Joint selection grows as P^N (3 drones x 3 corridors = 27 combos; 20 drones x 5 corridors ≈ 10^14).
- **Competing objectives:** (1) total flight cost (distance + headwind energy), (2) separation conflicts. Cheapest corridors tend to bunch together through the same segments.

## 2. Formulate

**Airspace model:** 4x4 grid of cells; each grid edge is a flight segment with a cost weight (1–3, models distance plus wind/energy). Candidate corridors per drone are pre-computed classically (3 cheap, mutually distinct staircase paths).

**Decision variables:** `x[i,p] ∈ {0,1}`, 1 if drone i flies candidate corridor p. 3 drones x 3 corridors = **9 binary variables = 9 qubits**, no slack variables needed.

**Objective (minimise):**

```
f(x) = Σ_i Σ_p c[i,p]·x[i,p]                     # total flight cost   (linear)
     + μ · Σ_{i<j} Σ_{p,q} s[i,p,j,q]·x[i,p]·x[j,q]   # shared segments (quadratic)
```

- `c[i,p]` = cost of corridor p for drone i
- `s[i,p,j,q]` = number of grid segments shared by those two corridors
- `μ` = trade-off weight. Sweeping μ traces the cost-vs-safety trade-off curve.

**Constraint:** `Σ_p x[i,p] = 1` for each drone i (one-hot). Converted to a penalty `P·(1 − Σ_p x[i,p])²` by `QuadraticProgramToQubo` (or kept exact with a constraint-preserving mixer, see §4).

**Why quantum-shaped:** the quadratic conflict terms are exactly the ZZ couplings of an Ising Hamiltonian, so the problem maps natively to QAOA. Without them it would be a plain assignment problem that the Hungarian algorithm solves exactly. Say this in the pitch; it pre-empts the "why quantum?" question.

- Feasible assignments: **27** (out of 2^9 = 512 bitstrings).
- Exact Pareto front (total cost, conflicts): **(19, 4), (20, 2), (21, 1), (22, 0)**. Each conflict removed costs extra flight energy, which is the trade-off to show on the results slide.

| μ | Exact optimum | Optimal assignment(s) (corridor per drone) |
|---|---|---|
| 0.25 | 20.0 | (1,2,1): cost 19, 4 conflicts |
| 0.75 | 21.5 | (1,1,2) or (1,2,2): cost 20, 2 conflicts |

Useful facts for the report:
- At μ=1.5 there are **three tied optima**, so QAOA "success" should count probability mass on *any* optimum.
- Point (21, 1) is only reached when μ is exactly 1 (a three-way tie), so a weighted sum can barely reach it. Mention this as a known limitation of weighted-sum multi-objective methods and as a possible extension (ε-constraint version).

## 4. Justify the quantum algorithm

- **Primary: QAOA** (`reps` p = 1, 2, 3). It is designed for diagonal Ising/QUBO cost Hamiltonians, the circuit is shallow at 9 qubits, and the approximation ratio vs depth is a clean, interpretable metric.
- **Comparison 1: SamplingVQE** with a hardware-efficient ansatz (e.g. `RealAmplitudes`), to show why a problem-structured ansatz (QAOA) helps.
- **Comparison 2 (the "technical extension" points): constraint-preserving QAOA.**
  - Start each drone's 3 qubits in a W-state (exactly one corridor chosen).
  - Use an XY ring mixer within each drone's qubit group.
  - Every sample is then feasible by construction, with no penalty P to tune.
  - Report the feasible-sample rate: penalty QAOA vs XY-mixer QAOA.
- **Optional:** CVaR objective (α ≈ 0.1–0.25), which often improves sampling-based QAOA.

**Core formulation sketch** (verify the API on day 1; the qiskit-optimization/algorithms APIs have changed between releases):

```python
from qiskit_optimization import QuadraticProgram
from qiskit_optimization.converters import QuadraticProgramToQubo

qp = QuadraticProgram("skylanes")
for i in range(3):
    for p in range(3):
        qp.binary_var(f"x_{i}_{p}")
linear = {f"x_{i}_{p}": cost[i][p] for i in range(3) for p in range(3)}
quad = {(f"x_{i}_{p}", f"x_{j}_{q}"): mu * s
        for (i, p, j, q), s in conflict.items() if s}
qp.minimize(linear=linear, quadratic=quad)
for i in range(3):
    qp.linear_constraint({f"x_{i}_{p}": 1 for p in range(3)}, "==", 1, f"one_corridor_{i}")

qubo = QuadraticProgramToQubo().convert(qp)
hamiltonian, offset = qubo.to_ising()   # 9-qubit SparsePauliOp
```

Then run `MinimumEigenOptimizer(QAOA(sampler, COBYLA(), reps=p))` against `MinimumEigenOptimizer(NumPyMinimumEigensolver())` as the exact reference. Fix all seeds: COBYLA initial point, sampler seed, instance seed.

## 7. Reflect: limitations to state honestly

- At this size, brute force is instant and always wins, and **no quantum speedup is claimed**. The project shows a correct mapping and behaviour trends, not advantage.
- Candidate corridors are pre-computed classically, so the quantum part does the *joint selection*, not the path search. That is a hybrid design, and the right one.
- Penalty weight P and trade-off weight μ need tuning, and penalty landscapes hurt QAOA feasibility (motivating the XY mixer).
- A shared segment is a proxy for conflict. Real deconfliction is 4-D (time-separated drones on the same segment are fine). Time slots are a natural extension: `x[i,p,t]`.
- Qubit count grows as N·P (linear), but the number of interaction terms can grow as N²·P², which costs gates and SWAPs on real hardware. The transpiled circuit itself needs qubit routing, which makes a good closing line for the pitch: "our routing problem had to be routed."
